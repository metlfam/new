# 2. КОНЦЕПЦИЯ ПРОДУКТА

## 2.1. Название

START

Слоган:

«Не нужно делать всё. Нужно просто начать».

Дополнительный текст:

«Преврати большую и страшную задачу в маленький шаг, который можно сделать прямо сейчас».

## 2.2. Главная проблема

Люди часто откладывают важные дела, потому что:

- задача кажется слишком большой;
- непонятно, с чего начинать;
- страшно сделать что-то неправильно;
- отсутствует мотивация;
- есть ощущение перегруженности;
- человек постоянно отвлекается;
- планирование кажется сложнее самой работы;
- человек боится потратить много времени;
- после нескольких неудачных попыток возникает чувство вины.

Приложение должно решать эти проблемы с помощью последовательных небольших действий.

## 2.3. Основной принцип

Пользователь не должен чувствовать, что перед ним сложный таск-менеджер.

Приложение должно восприниматься как спокойный персональный помощник, который говорит:

«Давай сделаем хотя бы один маленький шаг».

## 2.4. Целевая аудитория

Основная:

- студенты;
- школьники;
- молодые специалисты;
- фрилансеры;
- люди с большим количеством незавершённых задач;
- люди, испытывающие сложности с началом работы.

Возрастное ядро: 16–35 лет.

Однако интерфейс должен быть понятен пользователю любого возраста.

# 3. ТЕХНОЛОГИЧЕСКИЙ СТЕК

Использовать:

- React;
- TypeScript;
- Vite;
- Tailwind CSS;
- Lucide React для иконок;
- localStorage для сохранения пользовательских данных.

Допускается использовать небольшие дополнительные библиотеки, если они действительно улучшают продукт.

Для анимаций использовать CSS transitions либо Framer Motion, если библиотека уже доступна и её подключение не замедляет разработку.

Не использовать обязательный backend.

Не использовать базу данных.

Не требовать API-ключей.

Не требовать регистрацию.

Не подключать платные сервисы.

Приложение должно полноценно работать локально после установки зависимостей.

Команды запуска:

```bash
npm install
npm run dev
```

Команда проверки production-сборки:

```bash
npm run build
```

Необходимо корректно настроить TypeScript и сборку.

# 4. ОСНОВНОЙ ПОЛЬЗОВАТЕЛЬСКИЙ СЦЕНАРИЙ

Пользователь открывает приложение.

На экране отображается:

«Что ты откладываешь?»

Под вопросом находится большое поле ввода.

Placeholder:

«Например: подготовиться к экзамену по математике».

Пользователь вводит задачу.

Нажимает:

«Помоги мне начать →»

После этого приложение:

1. Анализирует текст задачи.
2. Предлагает несколько маленьких конкретных действий.
3. Выделяет один самый простой первый шаг.
4. Предлагает запустить пятиминутный таймер.
5. После завершения сессии спрашивает о результате.
6. Сохраняет прогресс.
7. Предлагает продолжить или завершить работу.

Весь путь от открытия сайта до запуска таймера должен занимать приблизительно 15–30 секунд.

# 6. ГЛАВНАЯ СТРАНИЦА

## 6.1. Основной экран

Сделать главный экран визуально выразительным, но минималистичным.

В верхней части:

Логотип START.

Рядом небольшой символ, ассоциирующийся с движением вперёд.

Основной заголовок:

«Самое сложное — начать».

Подзаголовок:

«Напиши, что откладываешь. Мы превратим это в маленький первый шаг».

Ниже расположить главное поле ввода.

Требования к полю:

- крупное;
- заметное;
- с приятным скруглением;
- с качественным focus-состоянием;
- поддерживает длинные названия задач;
- ограничение: 200 символов;
- счётчик символов не обязателен.

Кнопка:

«Разбить на шаги →»

Кнопка должна иметь красивую интерактивную анимацию.

При пустом вводе кнопка неактивна.

Пробелы в начале и конце должны удаляться.

Нельзя создать задачу, состоящую только из пробелов.

## 6.2. Быстрые примеры

Под полем ввода добавить кликабельные примеры:

- «Подготовиться к экзамену».
- «Убраться в комнате».
- «Начать заниматься спортом».
- «Написать курсовую».
- «Разобрать накопившиеся дела».

Нажатие на пример автоматически заполняет поле ввода.

Желательно, чтобы примеры выглядели как компактные интерактивные чипы.

## 6.3. Виджет прогресса

Ниже основной формы показать компактную статистику:

- минут в фокусе сегодня;
- завершённых сессий сегодня;
- текущую серию активных дней.

Для нового пользователя все значения равны нулю.

Не показывать выдуманную статистику.

## 6.4. Продолжение предыдущей задачи

Если у пользователя есть незавершённые задачи, отображать отдельный блок:

«Продолжим начатое?»

В блоке показать последнюю активную задачу.

Кнопка:

«Продолжить».

Нажатие открывает эту задачу.

# 7. СИСТЕМА РАЗБИЕНИЯ ЗАДАЧ

Это одна из важнейших функций приложения.

## 7.1. Назначение

Любую крупную задачу необходимо преобразовывать в несколько простых, конкретных и выполнимых действий.

Например:

Вход:

«Подготовиться к экзамену по физике».

Результат:

1. Открыть список экзаменационных тем.
2. Выбрать одну тему.
3. Прочитать основные определения.
4. Выписать три ключевые формулы.
5. Решить одну простую задачу.

При этом первый шаг должен быть максимально лёгким.

## 7.2. Обязательное ограничение

В MVP нет внешнего AI API.

Поэтому нельзя имитировать полноценный искусственный интеллект.

Необходимо реализовать локальный генератор шагов на основе:

- анализа ключевых слов;
- набора шаблонов;
- определения категории задачи;
- универсальных сценариев.

Система должна давать осмысленный результат без интернета.

Не показывать пользователю ложные утверждения, что его задачу обработала нейросеть.

В будущем архитектура должна позволять заменить локальный генератор настоящим AI API.

## 7.3. Категории задач

Реализовать категории:

### Учёба

Ключевые слова:

экзамен, учёба, выучить, изучить, уроки, домашка, математика, физика, конспект, тест, зачёт.

### Уборка

убраться, уборка, комната, квартира, порядок, вещи, посуда.

### Работа

работа, проект, отчёт, презентация, документ, письмо, задача, клиент.

### Спорт

спорт, тренировка, зал, зарядка, пробежка, упражнения.

### Творчество

написать, нарисовать, создать, придумать, дизайн, статья, книга.

### Организация

разобрать, организовать, спланировать, документы, дела, список.

### Универсальная

Если категория не распознана, использовать универсальный шаблон.

Совпадения проверять без учёта регистра.

Желательно учитывать распространённые словоформы.

При совпадении нескольких категорий выбирать категорию с наибольшим количеством релевантных ключевых слов.

## 7.4. Требования к генерации

Каждая задача должна получать 3–6 шагов.

Шаги должны:

- начинаться с глагола;
- быть конкретными;
- не содержать сложных формулировок;
- в большинстве случаев занимать не более 5–10 минут;
- не требовать завершения всей задачи сразу.

Не создавать абсурдные или нерелевантные шаги.

Для универсальной задачи использовать безопасный алгоритм:

1. Определить, какой результат нужен.
2. Подготовить всё необходимое.
3. Выбрать самое маленькое действие.
4. Выполнять его пять минут.
5. Отметить результат.

Первый шаг должен быть наиболее простым.

## 7.5. Редактирование

После генерации пользователь должен иметь возможность:

- изменять текст шага;
- отмечать шаг выполненным;
- удалять шаг;
- добавлять собственный шаг;
- изменять порядок шагов, если реализация укладывается в доступное время.

Для изменения порядка достаточно кнопок «Вверх» и «Вниз». Drag-and-drop не обязателен.

Не допускать пустых шагов.

Изменения должны сохраняться.

## 7.6. Экран результата

Заголовок:

«Большое дело начинается с малого».

Ниже отображается исходное название задачи.

Затем блок:

«Твой план».

Список шагов.

Первый незавершённый шаг визуально выделить.

Ниже основной CTA:

«Начать с 5 минут →»

Дополнительная кнопка:

«Вернуться к задачам».

# 8. ПЯТИМИНУТНЫЙ ТАЙМЕР

## 8.1. Основная функция

Создать красивый, крупный и точный таймер обратного отсчёта.

Стандартное время — 5 минут.

Экран должен помогать концентрироваться.

Минимум отвлекающих элементов.

## 8.2. Внешний вид

В центре экрана большой таймер:

05:00

Вокруг — круговой индикатор прогресса.

По мере выполнения сессии круг должен постепенно заполняться либо уменьшаться.

Под таймером:

«Сейчас важно только одно».

Ниже отображать текущий шаг.

Например:

«Открой список экзаменационных тем».

## 8.3. Управление

Кнопки:

- «Пауза».
- «Продолжить».
- «Завершить раньше».

Перед досрочным завершением необходимо подтверждение.

Текст:

«Завершить сессию?»

Варианты:

- «Продолжить работу».
- «Завершить сессию».

Пауза должна полностью останавливать отсчёт.

## 8.4. Выбор длительности

Доступные режимы:

- 2 минуты;
- 5 минут;
- 10 минут;
- 15 минут;
- 25 минут.

По умолчанию всегда предлагать 5 минут.

Длительность можно выбрать до запуска.

После запуска менять длительность текущей сессии нельзя.

## 8.5. Точность

Не реализовывать таймер простым уменьшением счётчика каждую секунду.

Использовать вычисление оставшегося времени на основе фактической временной метки окончания.

Это необходимо, чтобы таймер оставался точным при:

- переключении вкладок;
- сворачивании браузера;
- временном замедлении JavaScript-таймеров.

При паузе сохранять точное оставшееся время.

После возобновления вычислять новую временную метку окончания.

## 8.6. Завершение таймера

Когда время заканчивается:

- остановить отсчёт;
- сохранить завершённую сессию;
- показать экран результата;
- при разрешении пользователя воспроизвести ненавязчивый звук;
- предложить отметить выполненный шаг.

Не воспроизводить навязчивые или громкие звуки.

Не требовать разрешения на системные уведомления при первом посещении сайта.

## 8.7. Перезагрузка страницы

Активное состояние таймера должно сохраняться.

Если пользователь обновил страницу, приложение восстанавливает сессию.

Если время истекло, пока страница была закрыта, при следующем открытии корректно завершить сессию.

Не допускать повторного сохранения одной сессии.

Если пользователь поставил таймер на паузу, после перезагрузки он должен остаться на паузе.

После завершения показывать спокойное позитивное сообщение:

«Ты сделал главное — начал! 🎉»

Подзаголовок:

«Даже несколько минут движения вперёд имеют значение».

Показать:

- длительность сессии;
- название задачи;
- текущий шаг.

Затем вопрос:

«Удалось выполнить этот шаг?»

Кнопки:

- «Да, готово».
- «Частично».
- «Пока нет».

Логика:

### Да, готово

Отметить шаг завершённым.

Предложить перейти к следующему.

Оставить шаг незавершённым.

Предложить ещё одну короткую сессию.

Оставить шаг незавершённым.

Показать поддерживающий текст:

«Ничего страшного. Ты уже выделил время на задачу».

Предложить сократить действие или попробовать снова.

Не использовать обвинительные сообщения.

Не наказывать пользователя за незавершённую работу.

Кнопки после оценки:

- «Ещё 5 минут».
- «Вернуться к задачам».

Если все шаги выполнены, автоматически отметить всю задачу завершённой.

# 10. РАЗДЕЛ «МОИ ЗАДАЧИ»

## 10.1. Общий вид

Список созданных задач.

Каждая задача отображается в карточке.

Карточка содержит:

- название;
- категорию;
- дату создания;
- количество выполненных шагов;
- общее количество шагов;
- прогресс в процентах;
- текущий статус.

## 10.2. Статусы

- Активная.
- Завершённая.

Статус должен вычисляться из состояния задачи.

Если все шаги выполнены, задача завершена.

Если хотя бы один шаг незавершён, задача активна.

## 10.3. Фильтры

Добавить:

- Все;
- Активные;
- Завершённые.

По умолчанию отображать активные.

## 10.4. Поиск

Реализовать поиск по названию.

Поиск должен работать мгновенно.

Без серверных запросов.

## 10.5. Действия

Пользователь может:

- открыть задачу;
- отредактировать название;
- работать с шагами;
- удалить задачу;
- отметить шаги;
- продолжить работу.

Удаление должно требовать подтверждения.

При удалении задачи исторические записи уже завершённых фокус-сессий должны сохраняться для статистики.

## 10.6. Пустые состояния

Если задач нет:

«Пока здесь пусто».

Подзаголовок:

«Добавь первое дело. Мы поможем сделать первый шаг».

Кнопка:

«Создать задачу».

Если поиск ничего не нашёл:

«Ничего не найдено».

Предложить изменить поисковый запрос.

# 11. РАЗДЕЛ «ПРОГРЕСС»

Сделать приятную и мотивирующую страницу статистики.

## 11.1. Основные показатели

Показывать:

1. Всего минут в фокусе.
2. Количество завершённых сессий.
3. Количество выполненных шагов.
4. Количество полностью завершённых задач.
5. Текущую серию активных дней.
6. Лучшую серию активных дней.

## 11.2. Недельная активность

Реализовать простой график активности за последние семь календарных дней.

Для каждого дня показывать количество минут в фокусе.

Можно использовать CSS либо небольшую библиотеку графиков.

График должен:

- красиво выглядеть;
- быть адаптивным;
- корректно отображать нулевые значения;
- использовать реальные пользовательские данные.

## 11.3. Серия активных дней

Активным считается день, в который пользователь завершил минимум одну полноценную фокус-сессию.

Досрочно завершённые сессии не увеличивают серию.

Использовать локальную календарную дату пользователя.

Текущая серия:

- включает сегодняшний день, если он активен;
- если сегодня активности ещё не было, допускает продолжение серии, завершившейся вчера;
- обнуляется, если последний активный день был раньше вчерашнего.

Лучшая серия — максимальное количество последовательных активных календарных дней за всю историю.

## 11.4. Мотивационные сообщения

Показывать короткие сообщения в зависимости от прогресса.

Например:

0 сессий:

«Первый шаг ещё впереди. Начни с двух минут».

1 сессия:

«Отличное начало!»

5 сессий:

«У тебя уже формируется полезная привычка».

20 сессий:

«Посмотри, сколько ты уже сделал».

Не показывать ложные достижения.

Не применять агрессивную геймификацию.

# 15. ХРАНЕНИЕ ДАННЫХ

## 15.1. Структура задачи

```typescript
type TaskStatus = "active" | "completed";

interface Task {
  id: string;
  title: string;
  category: string;
  steps: Step[];
  createdAt: string;
  updatedAt: string;
  completedAt: string | null;
  status: TaskStatus;
}

interface Step {
  id: string;
  title: string;
  completed: boolean;
  completedAt: string | null;
}
```

ID генерировать через `crypto.randomUUID()` с безопасным fallback при необходимости.

Дата хранится в ISO 8601.

Статус и время завершения задачи обновлять согласованно с состоянием шагов.

Если пользователь снимает отметку с завершённого шага, задача снова становится активной.

## 15.2. Структура сессии

```typescript
type SessionStatus = "active" | "paused" | "completed" | "abandoned";

interface FocusSession {
  id: string;
  taskId: string;
  stepId: string;
  taskTitle: string;
  stepTitle: string;
  plannedDurationSeconds: number;
  actualDurationSeconds: number;
  startedAt: string;
  endedAt: string | null;
  status: SessionStatus;
}
```

Сохранённые копии названий позволяют отображать историю даже после удаления исходной задачи.

Для активной сессии дополнительно хранить:

```typescript
interface ActiveTimer {
  sessionId: string;
  remainingSecondsWhenPaused: number | null;
  endsAt: string | null;
}
```

`endsAt` используется при работающем таймере.

`remainingSecondsWhenPaused` — при паузе.

Во время восстановления ориентироваться на фактические временные метки.

interface Settings {

interface AppData {

# 16. БИЗНЕС-ЛОГИКА

## 16.1. Создание задачи

Алгоритм:

1. Получить текст.
2. Удалить пробелы по краям.
3. Проверить длину.
4. Определить категорию.
5. Сгенерировать шаги.
6. Создать уникальный ID.
7. Добавить дату.
8. Сохранить задачу.
9. Открыть экран задачи.

## 16.2. Отметка шага

При отметке:

- обновить completed;
- установить completedAt;
- пересчитать прогресс;
- проверить завершение всей задачи;
- сохранить изменения.

При повторном снятии отметки:

- completed = false;
- completedAt = null;
- статус задачи пересчитывается.

## 16.3. Прогресс задачи

Формула:

`completedSteps / totalSteps * 100`

Округлять до целого процента.

Не допускать деления на ноль.

Если шагов нет, задача не считается завершённой.

При удалении последнего шага предложить создать новый или удалить задачу.

## 16.4. Запуск фокус-сессии

Перед запуском:

- проверить наличие задачи;
- проверить наличие текущего шага;
- проверить допустимую длительность;
- проверить отсутствие другой активной сессии.

Одновременно может существовать только одна текущая фокус-сессия.

Если уже есть активная сессия, предложить вернуться к ней.

Нельзя запускать несколько параллельных таймеров.

## 16.5. Досрочное завершение

При досрочном завершении:

- записать фактически прошедшее время;
- установить статус abandoned;
- не увеличивать число завершённых сессий;
- не увеличивать серию активных дней;
- сохранять эту запись в истории для корректного восстановления данных.

Досрочно завершённая сессия не должна показываться как полноценная завершённая.

В статистике минут фокуса учитывать фактически отработанное время завершённых и досрочно прерванных сессий, без двойного подсчёта.

## 16.6. Восстановление

При повторном запуске:

- восстановить задачи;
- восстановить настройки;
- восстановить текущую сессию;
- пересчитать таймер;
- проверить, не завершилось ли время.

Если сессия закончилась в отсутствие пользователя, учитывать её ровно один раз.

# 30. ГЛАВНЫЙ ПРОДУКТОВЫЙ ПРИНЦИП

START — не обычный список дел.

Обычный список дел говорит человеку:

«Вот всё, что тебе нужно сделать».

START должен говорить:

«Не думай обо всём сразу. Вот один простой шаг. Давай начнём».

Каждый экран должен поддерживать именно эту философию.

При конфликте между добавлением новой функции и упрощением пользовательского пути выбирай упрощение.

При конфликте между анимацией и скоростью работы выбирай скорость.

При конфликте между впечатляющим количеством функций и надёжностью выбирай надёжность.

**Начинай реализацию проекта немедленно. Не задавай вопросов. Создай максимально качественный работающий MVP в пределах доступного времени.**
